# Zerith 夹指可见穿模修复

## 原因与修改

原指尖 box 的内侧面位于局部 `|y|=40.5 mm`，而 CAD 可见表面最内侧约为
`38.1444 mm`，允许红盒进入可见实体约 2.36 mm 后才发生代理接触。

转换器版本 5 保留上游模型、完整 visual OBJ、腕部及掌部代理，分别对每根
手指的指腹（局部 x 为 33–59 mm）和指尖（59 mm 至末端）生成凸碰撞 OBJ。
切分包含三角形边与截面的交点，避免只选顶点造成切分边界漏包。
每个凸体只覆盖一根手指的一段，不会填充两指间的夹持空间。安装根部仍使用
原有 box；本次修复范围是远端夹持表面，不宣称全机器人外观与碰撞完全一致。

本地生成物现在包括 35 个 visual OBJ 和 8 个碰撞 OBJ，共 43 个。
派生 URDF 的 mesh 引用数为 65，碰撞几何数仍为 53；没有新增碰撞过滤。
OBJ 仍不纳入 Git，可以通过原转换命令生成，`--check` 校验新增碰撞文件。

## 开口标定与调用影响

`src/zerith_gripper_config.py` 集中定义每指向内行程 38.14 mm。该值来自
CAD 最小间距向下取整，两指闭合后保留小于 10 微米的几何间隙，避免完全重合。
这属于仿真几何止点，不是硬件行程或机械限位实测值。

- `GripperAction(0.0)` 仍表示闭合。
- 全开值由 0.08 m 校准为 0.07628 m。
- 宽度是相对于几何闭合止点的读数；锥形指腹的局部间距会随接触位置变化。
- 直接写死 `GripperAction(0.08)` 的客户端需要使用
  `robot_spec.gripper.maximum_width_m`；超出有效范围的请求仍会被明确拒绝。
- 派生 URDF 的两指行程、公共 Adapter 及现有运行后端使用一致标定。

底座、导轨、目标盒位置、抓取标定、控制增益、摩擦及接触阈值均未调整。

## 验证

测试包含 CAD 顶点及面中心的凸包覆盖、闭合限位、宽度映射往返、空夹爪
3 秒动力学闭合，以及双臂腕部与开合组合共 162 组无自穿透姿态检查。
固定 seed 500 的首次完整抓取回归为 `lift_held`、277 steps，抬升
0.102855 m，稳定保持 3.1 s。10 Hz 接触日志中的最大指盒穿透为
7.55 微米；该采样结果不等于所有 1 ms 物理步的最大值。

测试记录：整套测试 115 项通过；补充闭合与宽度往返断言后，相关两组测试
共 17 项通过。开发仓库和实际 Quickstart checkout 的实现、派生 URDF、
manifest 与 8 个碰撞 OBJ 已逐文件比较一致。

用户已查看修复后的抓取效果，确认无明显问题，人工视觉验收通过。
旧 HTML 录制的是旧模型，重新打开旧 HTML 不会显示本次修复。
本修复尚未创建或移动任何发布 tag。
